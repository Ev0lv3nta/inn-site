# Сайт по ИНН

Тестовое DaData: [Python-пайплайн](https://github.com/Ev0lv3nta/inn-site) ищет основной
сайт организации и возвращает домен или `null`, если подтверждения не хватает.

Поиск работает через CRW REST API. За ним — SearXNG, Lightpanda и Chromium,
запущенный Playwright. Страницы сначала читаются по HTTP, при неудаче — через CRW.
Поиск бесплатный, ключи поисковых API не нужны. Название
организации берётся из публичного сервиса ФНС; если он недоступен, поиск продолжается.
LLM — Luna 6 через OpenRouter, reasoning `high`. Она платная, с общим лимитом расходов.
Публичный JSON страницы также читается как данные; JavaScript при HTTP-разборе не исполняется.

## Запуск

Нужны Python 3.11+, uv, ключ OpenRouter и работающий CRW. Собрать свой стек можно
по [инструкции](stack/README.md); подключения к частному серверу для этого не требуется.

```sh
uv sync --frozen
export OPENROUTER_API_KEY='ваш_ключ'
export CRW_URL='http://127.0.0.1:3080'
uv run inn-site --inn 7721581040
```

```json
{"domain": "dadata.ru"}
```

JSON можно подать через stdin. Источники и причины решения сохраняются отдельно:

```sh
echo '{"inn":"7721581040"}' | uv run inn-site
uv run inn-site --inn 7721581040 --trace reports/private/example.json
```

В stdout только JSON. Код `0` — завершённый поиск, включая обоснованный отказ;
`2` — неверный вход; `3` — сбой поиска, LLM или таймаут. Трассы содержат тексты
страниц и не попадают в Git. `--no-cache` отключает суточный кеш.

Для сайтов с Russian Trusted CA нужен отдельный набор сертификатов. Скрипт
скачивает сертификаты Госуслуг, проверяет закреплённые хеши и создаёт файл проекта:

```sh
uv run python stack/certificates.py
SSL_CERT_FILE="$PWD/.cache/russian-ca.pem" uv run inn-site --inn 7721581040
```

Системное хранилище не меняется, проверка TLS остаётся включённой.
Переменные перечислены в `.env.example`; сам файл `.env` автоматически не загружается.
Общий бюджет LLM по умолчанию — $0.25, журнал — `.cache/llm-spend.json`.
Он учитывает расходы этого проекта, а не всего аккаунта.

## Как принимается ответ

Первый запрос строится из юридического названия и региона ФНС с добавлением
«официальный сайт»; если записи нет, используется ИНН. Дальше модель выбирает
запросы и ссылки, читает реквизиты и определяет роль организации в тексте.
ИНН клиента, банка в счёте или директора другого юрлица не доказывает
владение сайтом. Python прикрепляет дословный фрагмент выбранной страницы и проверяет
точный ИНН, источник и домен. Сниппеты и карточки каталогов окончательным доказательством
не считаются. Подтверждённый действующий алиас одного бренда допустим; выбор между
разными брендами требует обоснования. Предварительно выбранный домен проходит
дополнительную проверку основного сайта. Домен выдаётся после завершения проверки
моделью и принятия свидетельств кодом; неверную цитату можно исправить один раз.

Один запуск ограничен девятью шагами модели, четырьмя поисками, шестью активными
кандидатами, двенадцатью URL и пятью минутами. Учитывается robots.txt. Домены и ИНН
из контрольного набора в алгоритме не зашиты.

## Проверка

```sh
uv run pytest
uv run ruff check .
uv run python scripts/evaluate.py --split all --no-cache
uv run python scripts/evaluate_llm.py
```

Первые две команды работают без сети и ключа. Остальные делают реальные запросы
и расходуют LLM-бюджет. [Результаты](reports/validation.md),
[эталоны](tests/cases.json), [принятые свидетельства](reports/decisions.json).
Сохранены и неудачные прогоны. Это небольшой набор известных случаев, а не оценка
качества на всём ЕГРЮЛ. `null` не доказывает отсутствие сайта.

[Ответы в PDF](docs/solution.pdf): 3 страницы теории и 3 страницы реализации.
[Теория](docs/theory.md) и [описание реализации](docs/practice.md) также доступны отдельно.
Собрать PDF заново:

```sh
uv run --group docs python scripts/build_pdf.py
# После публикации репозитория:
uv run --group docs python scripts/build_pdf.py --github-url https://github.com/USER/REPO
```

Код, тесты и документ подготовлены с Codex.
