# Задание 2. Поиск сайта по ИНН

Код: [GitHub](https://github.com/Ev0lv3nta/inn-site). Профиль: [Ev0lv3nta](https://github.com/Ev0lv3nta/).

## Что делает программа

Программа принимает `{"inn":"7721581040"}` и возвращает `{"domain":"dadata.ru"}`. Если подтвердить сайт не удалось, возвращает `{"domain":null}`. ИНН можно передать через `--inn` или JSON в stdin. В stdout попадает только ответ, пояснения и ошибки идут в stderr.

Формат ИНН и контрольная сумма проверяются до обращения к сети. Поддерживаются ИНН юридических лиц и ИП, хотя отдельной проверки качества на ИП пока нет. Неверный вход завершает программу с кодом 2, технический сбой с кодом 3, обычный ответ, в том числе обоснованный `null`, с кодом 0.

## Чем ищет и читает

Поиск идёт через CRW REST API и собственный SearXNG. Для чтения страниц используются HTTPX, BeautifulSoup и pypdf. Если этого недостаточно, программа обращается к CRW с Lightpanda и Chromium, запущенным через Playwright. Браузер нужен для страниц, содержимое которых появляется после исполнения JavaScript.

При чтении сохраняются футер, ссылки и публичные данные из JSON-LD и JSON состояния страницы. Это оказалось важно на практике: реквизиты могут находиться за пределами основного текста. Название и регион программа запрашивает в публичном сервисе ЕГРЮЛ/ЕГРИП ФНС. Если он недоступен, поиск продолжается по ИНН. Конфигурация и запуск стека есть в репозитории; доступ к серверу автора не нужен.

В итоговых прогонах использовался бесплатный поиск. Анонимная квота Exa закончилась, другие движки ограничивали запросы. Обновление парсера Yahoo в SearXNG помогло восстановить поиск по названию. Поддержка Tavily и Brave оставлена как дополнительный вариант, но выключена и проверена только на подставных ответах API. Версии поискового стека зафиксированы в документации.

Для анализа используется `openai/gpt-6-luna` через OpenRouter с reasoning `high`. Модель выбирает, что искать и читать дальше, и объясняет связь сайта с организацией. Ответ ограничен JSON Schema, затем проверяется Pydantic и обычным Python. Для этого достаточно небольшого цикла без отдельного агентного фреймворка.

LLM платная. Во время проверки миллион входных токенов стоил $0.10, выходных $0.50. Перед запросом программа проверяет тариф и резервирует верхнюю оценку расходов, после ответа записывает фактическую стоимость. По умолчанию бюджет составляет $0.25. Журнал защищён блокировкой от одновременных запусков. Платный поиск и автоматическая замена модели выключены.

## Как принимается решение

Сначала программа ищет точный ИНН в ФНС. Первый поисковый запрос состоит из юридического названия, региона и слов «официальный сайт». Если название не получено, используется ИНН в кавычках. Последующие запросы выбирает модель с учётом уже прочитанного.

Из выдачи собираются кандидаты и ссылки. Домены приводятся к общему виду через Public Suffix List с учётом кириллицы и частных зон. Каталоги помогают найти организацию и её сайт, но сами не становятся ответом. Модель выбирает страницы по подписям ссылок: контакты, оферты, реквизиты или документы.

Дальше LLM определяет, кому относится найденный ИНН. Например, реквизиты банка получателя или издателя отдельной книги не подтверждают принадлежность всего сайта. Текст страницы передаётся как данные; инструкции внутри него не должны управлять работой агента.

Для подтверждения модель указывает ID прочитанного источника. Программа сама берёт из него дословный фрагмент с ИНН и проверяет границы числа и домен. Поискового сниппета недостаточно. Если модель сослалась на неподходящий источник или исказила цитату для сравнения сайтов, ей даётся одна попытка исправить ответ. Если связь остаётся неясной, результатом будет `null`.

На каждом шаге модель может продолжить поиск, запросить до трёх страниц или закончить работу. Она видит историю, ошибки и оставшийся бюджет. Читать разрешено только уже найденные ссылки. Домен выдаётся после действия `finish` и проверки подтверждения. В выборе сайта нет регулярных выражений, подстановок для известных ИНН и заранее заданных адресов юридических страниц.

Предварительно выбранный сайт проходит дополнительную проверку: действительно ли он основной? Это нужно даже при одном найденном кандидате, который может оказаться отдельным проектом компании. Когда сайтов несколько, для выбора нужны поясняющие цитаты с обоих. При равноправных брендах программа возвращает `null`. Допустим и другой действующий адрес того же бренда, если его принадлежность подтверждена.

## Ограничения одного запуска

На поиск отведено пять минут, до девяти шагов модели, четырёх поисковых запросов, шести активных кандидатов и двенадцати URL. До трёх страниц читаются одновременно. Размер загрузки, число перенаправлений, страницы PDF и объём текста для LLM тоже ограничены.

При HTTP-переходах проверяются адреса частных и служебных сетей. Запрет robots.txt не обходится через удалённый браузер. Для публичного многопользовательского сервиса дополнительно потребуется изолировать сеть браузеров. Поиск и страницы кешируются на сутки; `--no-cache` отключает кеш. Параметр `--trace` сохраняет ход работы, источники, решения, время и расходы. В репозитории опубликованы краткие результаты и принятые фрагменты, полные журналы остаются локально.

## Как запустить

Нужны Python 3.11+, uv, ключ OpenRouter и CRW. Установка поискового стека описана в `stack/README.md`. Зависимости клиента устанавливаются командой `uv sync --frozen`. После настройки ключа пример запуска: `uv run inn-site --inn 7721581040`. Версии Python-пакетов закреплены в `uv.lock`, Playwright в `package-lock.json`.

Для банковских сайтов команда `uv run python stack/certificates.py` собирает отдельный набор сертификатов с корнями Госуслуг. Проверка TLS остаётся включённой, системное хранилище не меняется.

## Что проверено

90 тестов без сетевых запросов проходят командой `uv run pytest`. Проверка `uv run ruff check .` также проходит. Скрипты `evaluate.py` и `evaluate_llm.py` запускают проверки с настоящими API и расходуют бюджет. Ожидаемые ответы и контрольные URL из `tests/cases.json` алгоритму не передаются.

В последних результатах для каждого ИНН подтверждено 16 из 16 сайтов, ложных доменов: 0. В случае равноправных брендов получен null, неверный ИНН отклонён до обращения к сети. Это итог нескольких прогонов. В полном прогоне правильными были 14 из 18 ответов; после исправлений четыре проблемных случая проверены заново, все четыре прошли. Остальные 13 сайтов дополнительно проверены текущей моделью на сохранённых страницах, без нового поиска. Полного повторного прогона финальной версии по всем 18 входам не было. Неудачные результаты также сохранены.

Отдельно модель проверена на 17 подготовленных фрагментах с неоднозначными упоминаниями ИНН. Правильных ответов: 17, ложных доменов: 0. Простая проверка наличия ИНН на тех же текстах дала 4 правильных ответа и 13 ложных доменов. На этих примерах чтение контекста помогает отличить владельца сайта от стороннего упоминания. Тексты и ответы есть в репозитории.

В проверке нескольких брендов ожидаемый ответ пришлось изменить после чтения первичных страниц: выбор одного домена был необоснованным. Исходный неудачный результат сохранён. История прогонов находится в `reports/validation.md`, фрагменты, на которых основаны ответы, в `reports/decisions.json`.

## Что ещё нужно проверить

Примеры подбирались во время разработки, поэтому этот результат нельзя переносить на весь ЕГРЮЛ. Следующий шаг: собрать независимую выборку новых организаций, отдельно проверить ИП и группы компаний. Ошибки инструментов при этом нужно считать отдельно от обоснованных отказов. Проверка неверного ИНН не заменяет случай организации без сайта.

Требование точного ИНН снижает полноту: сайт может существовать без опубликованных реквизитов. Поисковый индекс бывает неполным, страницы недоступными, а модель может ошибиться в роли организации. Распознавание сканов, массовый сбор и обновление справочника в прототип не входят; их место описано в первой части.

При разработке кода, тестов и этого документа использован Codex. Решения проверялись на реальных поисковых запросах и отдельно на сохранённых текстах.
