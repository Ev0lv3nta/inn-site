# Задание 2. Поиск сайта по ИНН

Репозиторий: [GitHub](https://github.com/Ev0lv3nta/inn-site).
Профиль GitHub: [Ev0lv3nta](https://github.com/Ev0lv3nta/).

## Контракт и инструменты

Вход — `{"inn":"7721581040"}`, выход — `{"domain":"dadata.ru"}` или `{"domain":null}`. ИНН передаётся строкой; формат и контрольная сумма проверяются до сети. Поддержаны ИНН юрлиц и ИП; качество на ИП отдельно не оценивалось. Команда принимает JSON из stdin либо `--inn`. В stdout только ответ. Неверный вход имеет код завершения 2, сбой инструментов или таймаут — код 3 и причину в stderr; обоснованный отказ — код 0.

Поиск работает через CRW REST API с собственным SearXNG. Чтение использует HTTPX, BeautifulSoup и pypdf; при неудаче — CRW с Lightpanda и Chromium, запущенным Playwright. Для юридических сведений важен полный HTML с футером и ссылками, поэтому удалённое чтение не ограничено основным текстом статьи. Публичные данные из JSON-LD и JSON состояния страницы тоже извлекаются. При HTTP-разборе JavaScript не исполняется; удалённые браузеры могут выполнить его для загрузки страницы. Название и регион запрашиваются в публичном сервисе ЕГРЮЛ/ЕГРИП ФНС. Его недоступность не останавливает поиск. Частный сервер для запуска не нужен: конфигурация и скрипт запуска включены в репозиторий.

SearXNG обращается к публичным поисковым движкам, платных поисковых API в итоговых прогонах нет. Дополнительный шлюз Tavily/Brave выключен; он проверен моками, живых ключей нет. Обновление парсера Yahoo помогло восстановить поиск по названию после исчерпания анонимной квоты Exa и ограничений других движков. Версии CRW, SearXNG и Playwright зафиксированы в документации стека и отчёте проверки.

LLM — `openai/gpt-6-luna` через OpenRouter, reasoning `high`, строгая JSON Schema. Модель выбирает операции и определяет смысл связи; Pydantic и обычный Python проверяют форму ответа, источник и домен. Агентный фреймворк для такого цикла не нужен. Зависимости Python закреплены в `uv.lock`, Playwright — в `package-lock.json`.

LLM платная: тариф на момент запуска — $0.10/M входных и $0.50/M выходных токенов. Перед запросами проверяется цена из каталога. Бюджет по умолчанию — $0.25; журнал с блокировкой сначала резервирует верхнюю оценку, затем учитывает фактическую стоимость. Платный web search и автоматическая замена модели выключены. Бесплатный поиск не даёт промышленного SLA.

## Как проходит поиск

1. ФНС устанавливает субъект по точному ИНН. Первый запрос строится из краткого юридического названия (при его отсутствии — полного), региона и слов «официальный сайт». Это сохраняет юридическую форму и не требует отдельного вызова LLM. При отсутствии идентификации используется ИНН в кавычках. Дальнейшие запросы выбирает модель.
2. Поиск даёт кандидатов и ссылки. Домены нормализуются через Public Suffix List с учётом IDN и частных зон. Каталоги служат для идентификации и новых ссылок, но не становятся ответом. Модель выбирает страницы контактов, реквизитов, оферт и PDF по смыслу подписей ссылок.
3. LLM получает ограниченный текст и определяет роль: оператор сайта, стороннее упоминание или неясная связь. ИНН банка, клиента, издателя отдельной книги или руководителя другого юрлица не подтверждает владение сайтом. Веб-контент передаётся как недоверенные данные.
4. Для собственного сайта модель выбирает ID прочитанного источника. Python прикрепляет дословный фрагмент с ИНН и проверяет границы числа, источник этого кандидата и совпадение домена. Сниппет не подходит. Неподтверждённый источник или недословная сравнительная цитата возвращаются модели на исправление один раз; действительная неясность связи остаётся основанием для `null`.
5. Модель задаёт следующий запрос или до трёх URL для чтения. Ей передаются история, ошибки, найденные доказательства и остаток бюджета. JSON Schema и код ограничивают URL уже наблюдавшимися ссылками. Домен выдаётся только при действии `finish` и принятом свидетельстве. В логике выбора нет словарей юридических страниц, регулярных выражений и подстановок по известным ИНН.
6. Предварительно выбранный основной домен проходит дополнительную проверку, даже если найден только один кандидат. Действующий подтверждённый алиас одного бренда допустим. Разные собственные бренды требуют сравнения: корпоративный сайт и отдельный продукт можно различить с цитатами обоих сайтов. Одна широта каталога не доказывает основной бренд. Неясность даёт `null`.

## Пределы и запуск

Один запуск ограничен девятью шагами модели, четырьмя поисками, шестью активными кандидатами, двенадцатью URL и пятью минутами. Одновременно читаются три страницы. Ограничены размер загрузки, перенаправления, страницы PDF и контекст. Адрес проверяется на частные и служебные сети при каждом HTTP-переходе; запрет robots.txt не обходится удалённым чтением. Для многопользовательского сервиса дополнительно нужна сетевая изоляция браузеров.

Кеш поиска и страниц живёт сутки; `--no-cache` его отключает. `--trace` сохраняет запросы, URL, свидетельства, решения, настройки, время и расходы. Время получения не равно дате исходной страницы или её обновления. Полные трассы не публикуются; компактные результаты и принятые фрагменты входят в репозиторий. Технические сбои сохраняются отдельно от отрицательного результата.

Нужны Python 3.11+, uv, ключ OpenRouter и CRW. Запуск своего стека описан в `stack/README.md`. Клиент: `uv sync --frozen`, затем с экспортированным ключом `uv run inn-site --inn 7721581040`. Для банковских сайтов создаётся отдельный CA bundle из сертификатов Госуслуг: `uv run python stack/certificates.py`. Проверка TLS остаётся включённой, системное хранилище не меняется.

Офлайн-проверки: `uv run pytest` (90 тестов) и `uv run ruff check .`. Скрипты `evaluate.py` и `evaluate_llm.py` повторяют реальные проверки и расходуют LLM-бюджет. Эталоны и первичные URL из `tests/cases.json` не передаются алгоритму.

## Результаты и ограничения

Последние живые результаты по каждому ИНН: 16/16 подтверждённых основных сайтов, 0 ложных доменов. Пропусков на положительных эталонах: 0; технических сбоев: 0. После полного контроля повторно проверены четыре пропуска. Это объединение последних ответов, а не один безошибочный запуск.

| Проверка | Результат |
| --- | --- |
| Подтверждённые основные сайты | 16/16; ложных доменов 0 |
| Несколько собственных брендов | null, ambiguous |
| Неверный вход | null, код завершения 2 |

Текущая LLM дополнительно подтвердила остальные 13 сайтов на сохранённых свидетельствах, без нового поиска. Это известные входы после разработки, не слепой контроль и не оценка качества на всём ЕГРЮЛ. Предыдущие результаты, включая неудачные, сохранены в репозитории.

На 17 синтетических фрагментах LLM с проверкой свидетельства дала 17 правильных ответов и 0 ложных доменов. Простая проверка точного ИНН на тех же текстах: 4 правильных ответов и 13 ложных доменов. Это показывает пользу анализа роли организации на выбранных сложных примерах. Тексты и ответы сохранены в репозитории.

Наборы маленькие и целенаправленно подобраны. Ошибки инструментов не засчитываются как правильный отказ; неверный ИНН не изображает организацию без сайта. Эталон нескольких брендов был исправлен после аудита первичных страниц, исходный неудачный результат сохранён. Все этапы описаны в `reports/validation.md`, принятые свидетельства — в `reports/decisions.json`.

Строгий критерий ИНН снижает полноту: сайт может существовать без опубликованных реквизитов. Не реализованы OCR, массовый сбор, обновление справочника и очередь ручной проверки — они описаны в первой части. Возможны ошибки модели в роли организации и ограничения индекса или доступа. Следующий шаг — независимая разметка новых организаций, отдельные сегменты ИП и групп, калибровка порога и оценка расходов обновления.

Codex использован для реализации, тестов и документа. Выбор инструментов подтверждён реальными прогонами; качество поискового индекса и качество анализа оценивались отдельно.
