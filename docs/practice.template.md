## Контракт и выбор инструментов

Вход — `{"inn":"7721581040"}`, выход — `{"domain":"dadata.ru"}` или `{"domain":null}`. ИНН передаётся строкой; формат и контрольная сумма проверяются до сети. Поддержаны ИНН организаций и ИП, но качество на ИП отдельно не оценивалось. Команда принимает JSON из stdin либо параметр `--inn`. В stdout только ответ; технический сбой имеет код завершения 3 и отдельную причину в stderr. Некорректный вход имеет код 2.

Выбран собственный SearXNG: он объединяет публичную выдачу Google CSE, DuckDuckGo и Yahoo и не требует платного поискового API. Образ Docker закреплён по digest, конфигурация включена в репозиторий. Для чтения используются HTTPX, BeautifulSoup и pypdf; при сбое обычного чтения — базовый Jina Reader без ключа. Карточки организаций используются только для названия и неподтверждённых ссылок на сайт. Существующий CRW можно подключить переменной окружения; частная инфраструктура для запуска не требуется.

LLM — `openai/gpt-6-luna` через OpenRouter с reasoning `high` и строгой JSON Schema. Модель разбирает роль юридического лица в тексте. Pydantic проверяет форму ответа, обычный код — свидетельство и домен. Агентный фреймворк здесь не нужен: решения модели управляют небольшим циклом инструментов в Python. Версии зависимостей закреплены в `uv.lock`.

LLM платная: на момент проверки тариф составляет $0.10 за миллион входных и $0.50 за миллион выходных токенов. Перед запуском проверяется тариф из каталога провайдера. Общий бюджет по умолчанию — $0.25; журнал с блокировкой сначала резервирует верхнюю оценку, затем учитывает фактическую стоимость. Автоматической замены модели и платного web search нет. Бесплатные поисковые движки могут ограничивать запросы; это не промышленный SLA.

## Как проходит поиск

1. Поиск по ИНН даёт название и кандидатов. Контактный домен или ссылка из карточки тоже становятся кандидатами, но не готовым ответом.
2. Пайплайн нормализует домены через Public Suffix List, учитывая IDN и частные зоны, отсекает карточки каталогов и читает сайты. При необходимости переходит к контактам, оферте или реквизитам на глубину до двух переходов; читает текстовые PDF.
3. LLM получает ограниченный контекст и определяет роль: владелец/оператор, стороннее упоминание или неясная связь. Для собственного основного сайта она указывает ID источника и дословный фрагмент с ИНН. Текст страниц передаётся как недоверенные данные, а не инструкции.
4. Код принимает только существующий источник этого кандидата, буквальную цитату с точным ИНН и совпадающий домен. Поисковый сниппет не подходит. ИНН банка в счёте, клиента в договоре или организации в реестре не подтверждает владение сайтом.
5. Если подтверждения нет, модель выбирает вероятный сайт для адресного поиска реквизитов либо извлекает название для нового запроса. Название проверяется по источнику с ИНН; выбранный ID должен принадлежать переданным кандидатам.
6. Один подтверждённый основной домен возвращается. Недостаток свидетельств и несколько подтверждённых собственных доменов дают `null`. Даже если LLM назвала один из них узким, прототип не назначает основной автоматически. Сбой поиска сохраняется в журнале: уже прочитанные достаточные свидетельства позволяют завершить поиск, а неуспешный поиск с ошибкой получает технический статус.

## Пределы и воспроизводимость

Максимум одного запуска — три поиска, шесть активных кандидатов, двенадцать URL и четыре минуты. Одновременно читаются три страницы. Ограничены объём загрузки, число перенаправлений, страницы PDF и контекст LLM. Каждый HTTP-переход проверяется на адреса частных и служебных сетей; запрет robots.txt не обходится удалённым чтением. Это защита прототипа, а не обещание полной изоляции от DNS rebinding в многопользовательском сервисе.

Кеш поиска и страниц живёт сутки; его можно отключить. Время получения свидетельства не равно дате публикации страницы или обновления чужого кеша. `--trace` сохраняет запросы, URL, тексты, цитаты, версии настроек, время и стоимость. Полные трассы не публикуются; в репозитории есть компактные результаты и ссылки на принятые свидетельства.

Для запуска: Python 3.11+, uv, Docker с Compose и ключ OpenRouter. Команды: `uv sync --frozen`, `docker compose up -d --wait`, затем с экспортированным ключом `uv run inn-site --inn 7721581040`. Офлайн-проверки (65 тестов): `uv run pytest` и `uv run ruff check .`. Скрипты `evaluate.py` и `evaluate_llm.py` повторяют живые проверки. Они требуют сеть и расходуют LLM-бюджет.

## Ограничения и следующий шаг

Строгий критерий с ИНН снижает полноту: сайт может существовать без опубликованных реквизитов. Не реализованы OCR, массовый сбор, периодическое обновление справочника и ручная очередь — это описано в первой части. Возможны ошибки LLM в смысле настоящей цитаты, неиндексированные документы и географические ограничения доступа. Для внедрения нужны независимая разметка более широкой выборки, отдельные сегменты ИП и организаций без подтверждённого сайта, калибровка порога и оценка стоимости обновления.

Codex использован для реализации, тестов и подготовки документа. Выбор метода подтверждён сохранёнными результатами: одной проверки цифр недостаточно, а улучшение анализа не устраняет пропуски поискового индекса. Подробные результаты — `reports/validation.md`, короткие свидетельства — `reports/decisions.json`.

Источники: [SearXNG](https://docs.searxng.org/user/configured_engines.html), [Jina Reader](https://jina.ai/reader/), [Luna 6](https://developers.openai.com/api/docs/models/gpt-6-luna).
